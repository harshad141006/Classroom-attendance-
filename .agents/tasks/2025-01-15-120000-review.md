# Status lists for absent and OD students

The change adds three collapsible status list sections to the attendance dashboard: one each for absentees, internal OD, and external OD students. Each section automatically filters and displays students with the corresponding attendance status, sorted by roll number. Lists update immediately when attendance status changes.

**Watch for:** None. The implementation is complete and correct with no blocking concerns.

**Verdict**: APPROVED

## High-level view

The status lists feature is implemented as three new HTML sections placed after the attendance cards grid and styled with distinct colored headers. The `updateStatusLists()` function in JavaScript filters students by status, sorts them numerically by roll number using `localeCompare` with the `numeric: true` option, and renders them as bullet-point lists with roll number and name. The function is called in all four locations where attendance data changes: initial load, date change, status change, and the no-students fallback. Student data is HTML-escaped in the list items to prevent XSS. The existing summary banner and modal functionality remain unchanged.

## Status list HTML structure

The HTML adds a `.status-lists-section` container with three `.status-list-block` elements, one for each status category. Each block contains a colored header (using emoji ❌, 🟡, 🔵 for visual distinction) and a `<ul>` element with a unique ID: `absenteesList`, `internalOdList`, `externalOdList`. The section is placed after the `.attendance-section` and before the closing `.container` div, matching the user's requirement to display lists below the student cards. The structure is semantic and properly nested.

## Filter and sort implementation

The `updateStatusLists()` function iterates over all students and groups them into three arrays based on their current attendance status. Each array is then sorted using `localeCompare(b.rollNumber, undefined, { numeric: true, sensitivity: 'base' })`, which correctly handles roll numbers like "24CS073" and "24CS092" in numeric order rather than lexicographic order. The helper function `renderList()` generates the HTML: if an array is empty, it displays "None" with the `.status-list-none` class; otherwise, it maps each student to an `<li>` with a bullet and the format "Roll Number - Name". The `escapeHtml()` function is applied to both roll number and name to prevent XSS.

## Call sites for updateStatusLists

The function is called in four locations: `init()` after rendering attendance and updating the summary, `handleDateChange()` after loading and rendering attendance for the new date, `handleStatusSelect()` after saving and re-rendering attendance when a status changes, and `showNoStudents()` to clear the lists when no students exist. This ensures the lists are always in sync with the current attendance state. The no-students case clears the lists because students array is empty, so all three categories render as "None".

## CSS styling

The CSS defines six new classes: `.status-lists-section` for the container (uses flexbox column with 20px gap), `.status-list-block` for each category block (white background, rounded corners, shadow, padding), `.status-list-header` for the section headers (larger bold text with a bottom border), and color-specific header classes (`.absentees-header` in red, `.internal-od-header` in orange, `.external-od-header` in blue). List items use `.status-list-item` (default styling) and `.status-list-none` (gray italic for empty state). Responsive adjustments reduce padding and font size on mobile. The styles are consistent with the existing card and summary styling.
